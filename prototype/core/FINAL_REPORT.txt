API ENDPOINTS
================================================================================

Authentication:
  GET  /health                     → {"status": "ok"}
  GET  /auth/login                 → OAuth2 redirect to Google
  GET  /auth/callback              → Exchange code for JWT
  GET  /auth/dev-login             → Dev-only: issue JWT for DEV_MOCK_USER

Chat:
  POST /api/chat                   → SSE stream of chat response tokens
       Request: {"message": "...", "session_id": "uuid (optional)"}
       Response: Server-Sent Events with JSON tokens
  GET  /api/chat/history           → User's chat sessions and messages

================================================================================
DATABASE SCHEMA
================================================================================

SYSTEM DATABASE (system_db) - Read/Write:
  users
    - id UUID PK
    - oauth_sub VARCHAR UNIQUE
    - email VARCHAR UNIQUE
    - active BOOL DEFAULT true
    - created_at TIMESTAMP

  roles
    - id UUID PK
    - name VARCHAR(50) UNIQUE

  user_roles
    - user_id UUID FK users PK
    - role_id UUID FK roles PK

  role_policies
    - id UUID PK
    - role_id UUID FK roles
    - table_pattern VARCHAR

  user_policies
    - id UUID PK
    - user_id UUID FK users
    - table_pattern VARCHAR
    - policy_type VARCHAR(10) -- 'grant' or 'restrict'

  chat_sessions
    - id UUID PK
    - user_id UUID FK users
    - created_at TIMESTAMP

  chat_messages
    - id UUID PK
    - session_id UUID FK chat_sessions
    - user_id UUID FK users
    - role VARCHAR(10) -- 'user' or 'assistant'
    - content TEXT
    - chunk_ids JSONB -- List of chunk UUIDs used
    - guardrail_result VARCHAR(10) -- 'pass' or 'fail'
    - created_at TIMESTAMP

  request_log
    - id UUID PK
    - user_id UUID FK users (nullable)
    - endpoint VARCHAR
    - method VARCHAR
    - status_code INT
    - latency_ms INT
    - violation_chunk_ids JSONB (nullable)
    - severity VARCHAR (nullable) -- 'HIGH' for guardrail failures
    - created_at TIMESTAMP

VECTOR DATABASE (vector_db) - Read-Only:
  chunks
    - id UUID PK
    - content TEXT
    - embedding vector(1536)
    - metadata JSONB
      {
        "allowed_roles": ["role-uuid-1", "role-uuid-2"],
        "allowed_users": ["user-uuid-1"],
        "table_name": "source_table_name",
        "row_id": "source_row_id",
        "schema_hash": "hash-value"
      }
    - created_at TIMESTAMP
    - updated_at TIMESTAMP

    - Contains: sub (user_id), role_ids, email, exp
    - Does NOT contain: table patterns, policies, metadata
    - Implementation: app/core/jwt.py:31-48

[✓] CONSTRAINT 3: Access Filter in pgvector WHERE
    - Uses JSONB operators: metadata->'allowed_roles' ?|, ?
    - Filtering happens in SQL, NOT post-filter
    - Implementation: app/rag/retriever.py:50-61

[✓] CONSTRAINT 4: Post-Generation Guardrail
    - Re-verifies each chunk_id after LLM generation
    - Checks allowed_roles and allowed_users in metadata
    - Returns 403 if any chunk unauthorized
    - Does NOT write chat_messages on failure
    - Implementation: app/api/chat.py:130-155

[✓] CONSTRAINT 5: Metadata Stripped for LLM
    - ChunkSerializer removes all metadata
    - LLM context contains only plain text
    - LLM never sees allowed_roles, allowed_users, table_name, row_id
    - Implementation: app/rag/serializer.py

[✓] CONSTRAINT 6: Stateless RAG
    - No message history maintained
    - Only system_prompt + current context + current message → LLM
    - No conversation memory
    - Implementation: app/rag/chain.py

[✓] CONSTRAINT 7: No Data Leakage on Guardrail Failure
    - 403 response without writing chat_messages
    - Violation logged with severity=HIGH
    - Response: {"error": "Access denied"}
    - Implementation: app/api/chat.py:146-151

[✓] CONSTRAINT 8: All Requests Logged
    - RequestLoggingMiddleware logs every request
    - Captures user_id, endpoint, method, status_code, latency_ms
    - Logs violation_chunk_ids and severity on failures

RUNNING THE SERVICE
================================================================================

LOCAL DEVELOPMENT:
  1. Install dependencies:
     pip install -e .

  2. Setup environment:
     cp .env.example .env
     # Edit .env with your credentials

  3. Run migrations:
     alembic upgrade head

  4. Start server:
     uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

  1. Build image:
     docker build -t chat-core .

SUPPORT & TROUBLESHOOTING
================================================================================

Common Issues:

1. "Connection refused" to database
   - Check PostgreSQL is running
   - Verify SYSTEM_DSN and VECTOR_DSN in .env
   - Test connectivity: psql postgresql://...

2. "Invalid token" errors
   - Verify JWT_SECRET is set and consistent
   - Check token hasn't expired (JWT_EXPIRY_MINUTES)
   - Use /auth/dev-login for quick testing

3. OpenAI API errors
   - Verify OPENAI_API_KEY is correct
   - Check you have API credits
   - Verify account has access to gpt-4o

4. Migrations fail
   - Drop and recreate databases
   - Run: alembic upgrade head

5. Tests fail
   - Ensure pytest-asyncio is installed
   - Check Python version (requires 3.12+)
   - Verify asyncpg is installed for SQLite tests
