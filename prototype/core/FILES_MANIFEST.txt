DATABASE SCHEMA:
================

System Database (read/write):
  users             - User accounts (id, oauth_sub, email, active, created_at)
  roles             - Role definitions (id, name)
  user_roles        - User role assignments
  role_policies     - Policies granted via roles (role_id, table_pattern)
  user_policies     - User policy overrides (user_id, table_pattern, policy_type)
  chat_sessions     - Chat sessions (id, user_id, created_at)
  chat_messages     - Chat messages (id, session_id, role, content, chunk_ids, guardrail_result)
  request_log       - API request logs (user_id, endpoint, method, status_code, latency_ms)

Vector Database (read-only):
  chunks            - Embeddings with metadata (id, content, embedding, metadata, created_at)
  metadata fields   - allowed_roles[], allowed_users[], table_name, row_id, schema_hash

KEY FEATURES:
=============

1. OAuth2 Authentication
   - Google login redirect
   - JWT token issuance (sub, role_ids, email, exp)
   - Dev-mode bypass for testing

2. Access Control
   - Fresh policy resolution per-request
   - Role-based + user-specific overrides
   - Returns allowed table patterns

3. RAG Pipeline
   - pgvector retrieval with access filtering (metadata @> operators)
   - Metadata stripping before LLM (security)
   - LangChain chain: system prompt + context + message
   - Stateless: no message history

4. Post-Generation Guardrail
   - Verifies user can access all chunks used in response
   - 403 + no write if violation detected
   - Logs severity=HIGH violations

5. Request Logging
   - Middleware logs every request
   - User ID extraction from JWT
   - Latency and status code tracking

6. Type Safety
   - Full type hints throughout
   - Pydantic models for requests/responses
   - SQLAlchemy ORM with relationships
